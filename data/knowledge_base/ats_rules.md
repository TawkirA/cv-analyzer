# ATS (Applicant Tracking System) Rules and Requirements
## Overview
This document outlines critical rules and requirements for resumes to successfully pass through Applicant Tracking Systems (ATS).
## 1. File Format Requirements
### Acceptable Formats
- **PREFERRED**: .docx (Microsoft Word 2007+)
- **ACCEPTABLE**: .pdf (text-based, not image-based)
- **ACCEPTABLE**: .txt (plain text)
- **AVOID**: .jpg, .png, .gif, image-based PDFs, .pages, .odt
### Format-Specific Rules
- PDFs must contain selectable text (not scanned images)
- Word documents should use standard .docx format (not .doc)
- Avoid password-protected files
- File size should be under 5MB
- Use standard character encoding (UTF-8)
## 2. Parsing and Readability
### Document Structure
- Use standard section headings (Contact Information, Summary, Experience, Education, Skills)
- Maintain logical top-to-bottom, left-to-right reading order
- Avoid multi-column layouts (single column is safest)
- Use standard page margins (0.5" to 1")
- Stick to standard page sizes (Letter: 8.5" x 11" or A4)
### Text Elements
- Use standard, ATS-friendly fonts (Arial, Calibri, Georgia, Times New Roman, Trebuchet MS)
- Font size: 10-12pt for body text, 14-16pt for headers
- Avoid decorative or script fonts
- Do not use text boxes (text may not be parsed)
- Avoid headers and footers (information may be lost)
- Do not use WordArt or special text effects
### Formatting Elements to AVOID
- Tables (may cause parsing errors)
- Text boxes
- Columns
- Headers/footers containing critical information
- Graphics, logos, or images
- Hyperlinks (use plain text URLs)
- Special characters (©, ®, ™, ♦, •)
- Horizontal or vertical lines
- Shading or background colors
- Symbols for bullet points (use simple hyphens or asterisks)
## 3. Contact Information Requirements
### Required Elements
- Full name (first and last)
- Phone number (single format: xxx-xxx-xxxx or (xxx) xxx-xxxx)
- Email address (professional)
- City and State/Province (full country if international)
### Placement
- Place at the top of the document
- Use simple, linear format
- Avoid placing in headers or footers
- Each element on separate line or clearly separated
### Format Example
John Michael Smith
(555) 123-4567
john.smith@email.com
San Francisco, CA
LinkedIn: linkedin.com/in/johnsmith
## 4. Section Headers and Organization
### Standard Section Names (ATS-Recognizable)
- **Contact Information** / **Personal Information**
- **Professional Summary** / **Summary** / **Profile**
- **Work Experience** / **Professional Experience** / **Employment History**
- **Education** / **Academic Background**
- **Skills** / **Technical Skills** / **Core Competencies**
- **Certifications** / **Licenses**
- **Projects** (if applicable)
- **Awards** / **Honors** (if applicable)
- **Publications** (if applicable)
- **Volunteer Experience** (if applicable)
### Section Header Formatting
- Use standard capitalization (Title Case or ALL CAPS)
- Bold or slightly larger font acceptable
- Avoid special characters or decorative elements
- Maintain consistency throughout document
## 5. Work Experience Formatting
### Required Information
- Job title
- Company name
- Location (City, State)
- Employment dates (Month Year format: January 2020 or 01/2020)
- Bullet points describing responsibilities and achievements
### Date Formatting
**Acceptable formats:**
- January 2020 - December 2022
- Jan 2020 - Dec 2022
- 01/2020 - 12/2022
- 2020 - 2022
**Avoid:**
- Incomplete dates (just year without month)
- Non-standard separators
- Inconsistent formatting within document
### Structure Example
Senior Software Engineer
ABC Technology Company | San Francisco, CA
January 2020 - Present
    - Achievement-focused bullet point with metrics
    - Responsibility description with relevant keywords
    - Project accomplishment with quantifiable results
## 6. Education Formatting
### Required Information
- Degree type and major
- Institution name
- Graduation date (or expected graduation date)
- Location (optional but recommended)
### Optional Information
- GPA (if above 3.5 and recent graduate)
- Relevant coursework
- Academic honors
- Thesis/dissertation title (for advanced degrees)
### Format Example
Bachelor of Science in Computer Science
University of California, Berkeley | Berkeley, CA
Graduated: May 2018
GPA: 3.8/4.0
## 7. Keywords and Skills
### Keyword Optimization
- Include exact keywords from job description
- Use both acronyms and full terms (e.g., "SEO" and "Search Engine Optimization")
- Incorporate industry-specific terminology
- Use standard job titles and role names
- Include technical skills, tools, and technologies
### Skills Section Format
**Acceptable formats:**
- Simple comma-separated list
- Categorized lists (Technical Skills, Soft Skills, Languages)
- Simple bullet points
**Avoid:**
- Skill rating bars or graphics
- Pie charts or visual representations
- Skill matrices in tables
### Keyword Placement
- Naturally integrated into experience descriptions
- Dedicated Skills section
- Professional summary
- Project descriptions
- Certifications and training
## 8. Special Characters and Symbols
### AVOID These Characters
- Bullet point symbols (•, ◆, ■, ►)
- Mathematical symbols (≥, ≤, ±)
- Currency symbols other than $ (€, £, ¥)
- Trademark symbols (©, ®, ™)
- Fancy quotation marks (" " ' ')
- Em dashes and en dashes (— –)
- Accented characters (if avoidable)
### USE These Alternatives
- Hyphens (-) for bullet points
- Simple dashes (-) for date ranges
- Spell out "percent" or use "%"
- Standard apostrophes (')
- Standard quotation marks (")
- "USD" or "dollars" instead of currency symbols
## 9. Common ATS Parsing Issues
### Issues That Cause Parsing Failures
1. **Merged Information**: Name and contact info in single line
2. **Embedded Tables**: Work history in table format
3. **Text Boxes**: Information contained in floating text boxes
4. **Image Text**: Text within images or graphics
5. **Unusual Section Names**: Creative headers not recognized
6. **Inconsistent Formatting**: Mixed date formats, varying structures
7. **Special Fonts**: Decorative or non-standard fonts
8. **Complex Layouts**: Multi-column designs, sidebars
### Prevention Strategies
- Test resume by copying and pasting into plain text editor
- Ensure all information remains intact and in correct order
- Use online ATS scanners to test compatibility
- Keep formatting simple and consistent
- Prioritize content over design
## 10. ATS Scoring Factors
### Factors That Improve ATS Scores
1. **Keyword Match**: Alignment with job description keywords
2. **Relevant Experience**: Years of experience matching requirements
3. **Education Match**: Degree requirements met
4. **Skills Match**: Technical and soft skills alignment
5. **Job Titles**: Similar or relevant position titles
6. **Industry Experience**: Relevant sector background
7. **Certifications**: Required or preferred credentials
8. **Location**: Geographic proximity (if relevant)
### Factors That Lower ATS Scores
1. **Missing Keywords**: Lack of job description terminology
2. **Employment Gaps**: Unexplained periods without work
3. **Job Hopping**: Frequent short-term positions
4. **Irrelevant Experience**: Unrelated work history
5. **Parsing Errors**: Unreadable formatting
6. **Typos and Errors**: Spelling and grammatical mistakes
7. **Incomplete Information**: Missing dates, locations, or details
## 11. Testing and Validation
### ATS Compatibility Testing Methods
1. **Plain Text Test**: Copy entire resume into Notepad/TextEdit
   - Check if all information is present
   - Verify correct order and structure
   - Look for garbled text or missing content
2. **PDF Text Selection Test**: 
   - Attempt to select and copy all text
   - Ensure text is selectable (not an image)
3. **Online ATS Scanners**:
   - Jobscan.co
   - Resume Worded
   - TopResume ATS checker
4. **Keyword Analysis**:
   - Compare resume keywords to job description
   - Ensure 60-80% keyword match for competitive positions
### Validation Checklist
- [ ] File format is .docx or text-based PDF
- [ ] Contact information is at top in simple format
- [ ] Standard section headers used throughout
- [ ] No tables, text boxes, or columns
- [ ] Standard fonts (Arial, Calibri, etc.)
- [ ] No images, graphics, or logos
- [ ] Simple bullet points (hyphens or asterisks)
- [ ] Consistent date formatting
- [ ] Keywords from job description included
- [ ] All text is selectable in PDF version
- [ ] Plain text test shows correct formatting
- [ ] No special characters or symbols
- [ ] File size under 5MB
- [ ] Spelling and grammar checked
## 12. ATS System Types
### Major ATS Platforms
1. **Taleo (Oracle)**: Strict parsing, prefers .docx
2. **Workday**: Good PDF parsing, keyword-focused
3. **Greenhouse**: Modern parsing, handles formatting well
4. **iCIMS**: Standard parsing capabilities
5. **Lever**: Good with both .docx and PDF
6. **BambooHR**: Small business focused, basic parsing
7. **SAP SuccessFactors**: Enterprise-level, strict requirements
8. **Bullhorn**: Recruiting-focused, keyword emphasis
### System-Specific Considerations
- **Conservative Approach**: Format for strictest systems (Taleo)
- **File Format**: When in doubt, use .docx
- **Testing**: Test with multiple ATS scanners
- **Adaptation**: Customize for known company ATS if possible
## 13. Compliance and Legal Considerations
### Information to EXCLUDE (Legal/Discrimination)
- Photograph or headshot
- Date of birth or age
- Marital status
- Number of children
- Religious affiliation
- Political affiliations
- Social Security Number
- Full home address (city and state sufficient)
- Physical characteristics
- Disability status (unless relevant accommodation needed)
### Privacy Protection
- Use professional email address
- Consider Google Voice number for privacy
- Limit personal information
- Avoid social media links unless professional (LinkedIn acceptable)
## 14. Mobile Optimization
### Mobile ATS Considerations
- Many recruiters review on mobile devices
- Keep resume to 1-2 pages
- Use adequate white space
- Ensure text is readable at smaller sizes
- Avoid tiny fonts (minimum 10pt)
- Test PDF rendering on mobile devices
## 15. Version Control and Tracking
### Best Practices
- Save master version with clear naming: "FirstName_LastName_Resume_Master"
- Create customized versions for specific applications
- Include date in filename: "John_Smith_Resume_2024"
- Keep both .docx and PDF versions
- Track which version sent to which company
- Update regularly with new skills and experience
## 16. International ATS Considerations
### Regional Differences
**United States:**
- No photo
- No date of birth
- Education after experience (unless recent graduate)
- 1-2 pages standard
**Europe (CV format):**
- Photo sometimes expected
- More detailed, longer format acceptable
- Europass format recognized
- May include date of birth
**Asia-Pacific:**
- Photo often expected
- More detailed personal information
- May include family information
- Longer formats acceptable
**Middle East:**
- Photo usually required
- Detailed personal information
- May need multiple language versions
### Adaptation Strategy
- Research target country norms
- Adjust format for regional expectations
- Maintain ATS compatibility regardless of region
- Consider cultural differences in presentation
## Summary: Critical ATS Rules
### Top 10 Must-Follow Rules
1. Use .docx or text-based PDF format
2. Avoid tables, text boxes, and columns
3. Use standard section headers
4. Include keywords from job description
5. Use simple, standard fonts
6. Place contact info at top in simple format
7. Avoid graphics, images, and special characters
8. Use consistent date formatting
9. Keep formatting simple and clean
10. Test with plain text conversion
### Success Metrics
- **70-80% keyword match**: Competitive threshold
- **0 parsing errors**: Goal for format testing
- **100% information retention**: In plain text test
- **1-2 pages**: Optimal length for most positions
- **10-15 seconds**: Time to find key information
